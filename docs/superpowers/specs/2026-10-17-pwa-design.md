# Этап 6а — `ft/pwa`: внешний вид и PWA

Дата: 2026-10-17 · Статус: реализовано · Ветка: `ft/pwa` (от `master`)

## Цель
Bitewise ставится на экран телефона как приложение, не показывает белый экран без сети, а тему и акцентный цвет можно выбрать вручную — выбор запоминается на устройстве и применяется без мигания.

**Готово, когда:**
- тема и акцентный цвет меняются на экране «Оформление», переживают перезагрузку и не мигают при открытии;
- prod-сборка на `localhost`: Chrome видит manifest и иконки и предлагает установку, service worker зарегистрирован, без сети открывается «Нет сети», переход посреди работы показывает плашку и сам завершается, когда сеть вернулась;
- `pnpm lint`, `pnpm test`, CI зелёные; ui-checker на 375 px.

## Отступления при реализации
- CSS-переменные тем не пишутся руками в `globals.css`: `appearanceCss()` собирает их из `APPEARANCE` в config и кладёт `<style>` в `<head>` — контраст проверяется тестом по тем же цифрам, что видит пользователь.
- Service worker — не файл `public/sw.js`, а route `/sw.js` из `lib/pwa/service-worker.ts`: пути и версия кэша из config, поведение проверено тестом на подставных `self`/`caches`.
- Строка установки читает устройство через `useSyncExternalStore` (серверный снимок — `null`), а не `useState` + эффект: правило lint React запрещает `setState` в эффекте; гидрация так же без расхождений.
- Символы «✓» и «›» — в `ru.ts` (`appearance.checkMark`, `profile.openArrow`).
- По ревью: cookie названы `bw-theme` / `bw-accent` (cookie не делятся по портам, «theme» — частое имя), повтор имени везде читается по первому значению; `theme-color` переписывается при каждом изменении `<head>` (Next заново рендерит мета-теги на навигации); `beforeinstallprompt` ловит ещё один inline-скрипт в `<head>` — событие могло прийти до гидрации; переключатели «Граммы / Порции» и «Сегодня / Вчера» тоже получили акцент.
- Автоповтор `useOffline` может задвоить действие, если ответ потерян после записи, — #95; CSP по хэшу несовместим с inline-скриптами Next — разбор в #18.

## Внешний вид
### Как применяется
Выбор — в cookie `theme` и `accent` (год, `SameSite=Lax`, `path=/`, не httpOnly: их читает скрипт; секретов нет). Корневой layout cookie на сервере **не читает**: под `cacheComponents` это сделало бы все экраны «по запросу». Вместо этого inline-скрипт в `<head>` до первой отрисовки ставит `data-theme` и `data-accent` на `<html>` (рецепт Next 16 «Preventing flash before hydration»). Скрипт принимает только значения из списка `APPEARANCE`; текст скрипта собирается из config функцией в `lib/appearance.ts`, а не пишется руками. В dev Strict Mode сбрасывает атрибуты `<html>` при повторном монтировании — клиентский компонент повторно применяет их в `useLayoutEffect`.

Отступление от формулировки этапа в PROJECT_PLAN («сервер рисует нужную тему»): тему ставит скрипт в `<head>`, результат тот же — без мигания.

Следствие для 6б: полный CSP (#18) разрешает этот скрипт по хэшу `sha256-…` (статичен, заранее собранные страницы не страдают).

### Токены (`app/globals.css`)
- `--background`, `--foreground` — как сейчас.
- `--accent` — заливка кнопок, прогресса, выбранной плитки, уведомления.
- `--on-accent` — текст на заливке.
- `--accent-text` — ссылки, ★, рамка фокуса на обычном фоне.

Тема: без `data-theme` — системная (`prefers-color-scheme`), `light`/`dark` — принудительно. Вариант `dark:` Tailwind переопределяется (`@custom-variant`), чтобы учитывать и выбор, и систему. `color-scheme` и `<meta name="theme-color">` следуют выбранной теме. «Графит» = `--accent: var(--foreground)`, `--on-accent: var(--background)` — ровно нынешний вид.

### Контраст
`contrastRatio` (WCAG 2.x) в `lib/appearance.ts`; тест по всей палитре в обеих темах: `--on-accent` на `--accent` и `--accent-text` на `--background` — не меньше `APPEARANCE.minContrast = 4.5`.

### Экран «Оформление» (`/profile/appearance`)
- Три плитки темы: «Системная / Светлая / Тёмная».
- Шесть кружков цвета: название для экранного диктора, галочка у выбранного.
- Тап — экран перекрашивается сразу, server action `saveAppearanceAction` проверяет значение zod и ставит cookie, уведомление «Сохранено».
- Сервер читает cookie внутри `<Suspense>` только на этом экране — чтобы отметить текущий выбор.
- Уведомление получает тень и обводку цветом фона — отделяется от цветной кнопки под ним.

## PWA
### Manifest и иконки
- `app/manifest.ts`: «Bitewise», `start_url: "/"`, `display: "standalone"`, `lang: "ru"`, `orientation: "portrait"`, фон и `theme_color` — графит, тексты — из `ru.ts`.
- Иконка — одна SVG-фигура в `components/brand/bite-mark.tsx`, PNG собирает Next через `ImageResponse` (`next/og`) при сборке, без `sharp`:
  - `app/icon.tsx` — favicon (вместо `app/favicon.ico` из шаблона);
  - `app/apple-icon.tsx` — 180 px;
  - 192 и 512 px «any» и «maskable» (фигура в безопасной зоне 80 %) — для manifest.

### Service worker (`public/sw.js`, без библиотек)
- `install`: кэширует офлайн-страницу и иконки (кэш с версией из config; старые версии удаляются в `activate`).
- `fetch`: только навигации (`request.mode === "navigate"`) — сеть, при ошибке сети — офлайн-страница. Остальное (данные, server actions, JS, CSS) не трогается: у JS/CSS неизменяемые имена с хэшем, браузер держит их сам, а свой кэш — источник «застрявшей версии» после деплоя.
- Регистрируется только в prod-сборке (клиентский компонент в корневом layout).

### Страница «Нет сети»
Статический route handler отдаёт самодостаточный HTML со встроенными стилями: «Нет подключения к интернету. Проверьте сеть и нажмите „Повторить"» и кнопка «Повторить» (перезагрузка). Тексты — из `ru.ts`, тема и акцент — тем же скриптом из `<head>`.

### Обрыв посреди работы
`experimental.useOffline: true` в `next.config.ts`; клиентская плашка в корневом layout на хуке `useOffline` (`next/offline`): «Нет сети — продолжу, когда появится» (`role="status"`). Флаг экспериментальный — отключается одной строкой.

### «Установить на телефон» (профиль)
Клиентский компонент рядом со ссылкой «Оформление»:
- есть `beforeinstallprompt` (Android-Chrome) — кнопка «Установить», открывает системный диалог;
- iPhone/iPad Safari — «Нажмите „Поделиться" → „На экран Домой"»;
- уже открыто с экрана (`display-mode: standalone`) или браузер не умеет — строки нет.

## Данные
БД не меняется, миграций нет.

## Настройки (`lib/config.ts`)
- `APPEARANCE`: темы, палитра (по два оттенка), значения по умолчанию, имена и срок cookie, `minContrast`.
- `PWA`: цвета manifest, размеры иконок, доля безопасной зоны maskable, путь офлайн-страницы, имя кэша с версией.

## Тесты
- Юнит (`lib/appearance.test.ts`): разбор cookie (мусор и подставленные значения → по умолчанию), строка cookie, `themeColor`, `contrastRatio` на эталонных парах, контраст всей палитры, inline-скрипт на подставном `document` ставит только разрешённые атрибуты.
- Схема server action: неверные тема и цвет отклоняются.
- Manifest: поля и иконки; офлайн-страница: HTML с текстами из `ru.ts`.
- `public/sw.js` и плашку проверяет ui-checker на prod-сборке (режим «без сети» в браузере).
- Субагенты: reviewer, security-reviewer (server action, cookie под inline-скриптом, service worker), ui-checker на 375 px (обе темы, все цвета, перезагрузка без мигания, офлайн-страница, плашка, строка установки).
