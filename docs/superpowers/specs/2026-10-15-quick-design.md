# Этап 5 — `ft/quick`: скорость ввода

Дата: 2026-10-15 · Статус: реализовано · Ветка: `ft/quick` (от `master`)

## Цель
Частые записи — в пару тапов: то, что ешь регулярно, добавляется без поиска и без экрана количества; весь привычный приём пищи повторяется одним тапом; «просто 450 ккал» записывается без продукта.

**Готово, когда:** вчера записан завтрак «Овсянка 60 г + Кофе с молоком 250 г»; сегодня каждый продукт добавляется за 2 тапа («+ Добавить» → тап по недавнему), а весь завтрак — за 1 тап («Повторить»); ошибочное добавление отменяется одним тапом. `pnpm lint` и `pnpm test` зелёные, CI зелёный, ui-checker на 375 px.

## Принятые решения (обсуждение 2026-10-15)
| Вопрос | Решение | Почему |
| --- | --- | --- |
| Что такое «2 тапа» | один продукт: «+ Добавить» → тап по недавнему или избранному записывает его сразу, с количеством из последней записи | экран количества не нужен для того, что ешь одинаково |
| Защита от ошибки | возврат на день и уведомление на 5 с «Добавлено — Отменить»; в списке у продукта видно, с каким количеством он добавится | вслепую не записывается, ошибка снимается одним тапом |
| Недавние | сначала продукты этого приёма пищи, от последнего, без повторов, до 8; добор из других приёмов; количество — из последней записи | утром наверху завтрак, а не вчерашний ужин |
| Избранное | ☆ на карточке продукта и на странице блюда; блок «Избранное» над «Недавними», без дублей; тап — как у недавних; ни разу не записанный продукт открывает экран количества | держать под рукой то, что ешь не каждый день |
| Повтор приёма пищи | кнопка у пустого приёма: «Повторить: Овсянка, Кофе · 420 ккал» — копия записей последнего дня, где этот приём был заполнен | весь привычный завтрак — один тап; только у пустого приёма, чтобы не задвоить |
| Быстрый ввод ккал | запись без продукта: `food_id` необязателен, снимок «100 г × ккал на 100 г»; название и Б/Ж/У необязательны | итоги дня в `lib/nutrition.ts` не меняются; без служебных продуктов и второй таблицы |
| Текст уведомления | только известные ключи из словаря: «Добавлено — Отменить», «Добавлено записей: N — Отменить», без названия продукта | текст из URL не выводится (решение партии 5); новая запись и так видна в дне |

## Отступления при реализации
- Недавние выбираются из последних `QUICK.recentScanEntries = 500` записей и ранжируются в коде, а не одним SQL-запросом с окнами.
- Быстрое добавление, повтор и звёздочка — в `lib/diary/quick-repo.ts` (без цикла импортов с `repo.ts`); общая проверка лимитов — `checkEntryLimits`.
- Повторённые записи получают `created_at = now() + i мкс`: одна вставка делит `now()`, иначе порядок в дне терялся.
- Поиск стоит над блоками «Избранное» и «Недавние»: запрос заменяет их на месте, поле не прыгает.
- Повтор одной записи — уведомление «Добавлено», а не «Добавлено записей: 1».
- Живой итог ккал — `previewKcal` в `lib/amount.ts`; контекст записи для нового продукта — `parseEntryContext` в `lib/diary/schema.ts`.

## Данные (`db/schema.ts`, через `/db-change`)
### `favorites` (новая)
`user_id` (→ users, cascade), `food_id` (→ foods, cascade), `created_at`; первичный ключ `(user_id, food_id)`; индекс по `food_id` (каскад при удалении продукта). Мягко удалённый продукт из избранного не показывается.

### `diary_entries`
- `food_id` — необязательный (быстрая запись).
- CHECK: запись без продукта не имеет порции (`food_id IS NOT NULL OR portion_label IS NULL`).
- Быстрая запись: `food_name` — название или «Быстрый ввод», `grams = 100`, `kcal_100` = введённые ккал, `protein_100/fat_100/carbs_100` = введённые граммы или 0.

### Лимиты и настройки (`lib/config.ts`)
- `QUICK.recentLimit = 8`, `QUICK.maxFavorites = 100`, `QUICK.undoMs = 5000`.
- `MEAL_BY_HOUR` — границы приёма по времени суток: до 11 — завтрак, до 16 — обед, до 21 — ужин, иначе перекус (для «В дневник» со страницы блюда).
- Быстрый ввод: `QUICK.kcal = { min: 1, max: 5000 }` за запись (больше — опечатка, а не еда), Б/Ж/У — 0–`DIARY_LIMITS.grams.max` г, название — как у продукта (`FOOD_LIMITS.nameLength`).

## Серверная логика
### Чтение (`lib/diary/quick.ts` + репозиторий, тесты на тестовой БД)
- `listRecentFoods(userId, meal, limit)` — последние записи с продуктом (не быстрые, продукт виден и не удалён), без повторов по `food_id`: сначала этот приём, затем остальные; каждой — последнее количество (граммы или снимок порции × количество) и ккал по **текущим** цифрам продукта.
- `listFavoriteFoods(userId)` — избранное с тем же «последним количеством» (или без него).
- `findRepeatSource(userId, date, meal)` — последний день до `date`, где у этого приёма есть записи, и его записи; `null`, если приём на `date` не пуст или повторять нечего.

### Действия (`app/(app)/diary/actions.ts`, zod на всё, что пришло из браузера)
- `quickAddAction(foodId, date, meal)` — запись с последним количеством продукта (снимок порции из последней записи — порцию могли удалить); те же лимиты и `lockUserWrites`; без последней записи — на экран количества.
- `repeatMealAction(date, meal)` — копирует записи источника со снимками; отказ, если приём уже не пуст; лимит записей за день — на всю пачку, под одной блокировкой.
- `undoAddAction(entryIds)` — удаляет только свои записи из списка (≤ размера пачки); чужие и удалённые молча пропускает.
- `quickKcalAction(date, meal, values)` — быстрая запись; правка — `updateQuickEntryAction`.
- `toggleFavoriteAction(foodId)` — ставит/снимает ☆; продукт должен быть виден пользователю; лимит избранного.

Добавление и повтор возвращаются на день с `?toast=added|addedMany&undo=<id,…>`; `ToastHost` берёт id в состояние, сразу убирает их из URL и показывает «Отменить» 5 с.

## Экраны (375 px, тексты из `ru.ts`, тап-зоны ≥ 44 px)
- **Главная:** у пустого приёма — кнопка «Повторить: … · N ккал» (длинный список: «Овсянка, Кофе и ещё 2»); быстрая запись в списке — только ккал; тап по ней — правка «ккал / Б / Ж / У».
- **«+ Добавить»:** переключатель «Сегодня / Вчера» (#16, только для сегодня и вчера) · «Ввести только калории» · «Избранное» · «Недавние» · поиск. Блоки скрываются, когда в поиске есть запрос. Строка: «Овсянка · 60 г · 210 ккал»; тап записывает; кнопка «…» — экран количества.
- **«Ввести только калории»:** ккал (обязательно), название, Б/Ж/У, приём пищи, «Добавить».
- **☆/★** у названия на карточке продукта и на странице блюда.
- **Экран количества (#15):** живая строка «= 210 ккал» той же функцией из `lib/nutrition.ts`.

## Ошибки
- Лимит записей или удалённый продукт при мгновенном добавлении — сообщение над списком на экране «+ Добавить».
- Повтор, когда приём уже не пуст (вторая вкладка), — «уже заполнено», день обновляется.
- Чужие или уже удалённые id в «Отменить» — без ошибки и без эффекта.

## Тесты
- Юнит: последнее количество и ккал строки, обрезка подписи повтора, `MEAL_BY_HOUR`, разбор `undo`.
- Тестовая БД: порядок и добор недавних, исключение быстрых и удалённых, избранное без дублей и с лимитом, мгновенное добавление (последняя порция удалена — снимок остаётся), повтор (пустой/не пустой приём, лимит дня), отмена (чужие id), быстрая запись и её правка, чужие `foodId`/`entryId` везде.
- Субагенты: reviewer, security-reviewer (новые действия с id из браузера), ui-checker по сценарию «Готово, когда».
