# Этап 5 — `ft/quick`: план реализации

> **Для исполнителя:** обязательный навык — superpowers:executing-plans (или superpowers:subagent-driven-development). Шаги — чекбоксы `- [ ]`.

**Цель:** частые записи в пару тапов — мгновенное добавление из недавних и избранного, повтор приёма пищи, быстрый ввод ккал, плюс issues #12–#16.

**Архитектура:** две миграции (`favorites`, необязательный `diary_entries.food_id`); чтение «недавних», «избранного» и «источника повтора» — в `lib/diary/quick-repo.ts`, чистые функции — в `lib/diary/quick.ts`; новые server actions в `app/(app)/diary/actions.ts` возвращают на день с `?toast=…&undo=…`; экран «+ Добавить» получает серверный блок `QuickLists`, который `FoodSearch` показывает, пока запрос пуст.

**Стек:** Next.js 16 (App Router, cacheComponents), React 19, TypeScript strict, Drizzle + Postgres, zod 4, Vitest, Tailwind v4.

**Спека:** `docs/superpowers/specs/2026-10-15-quick-design.md`

## Глобальные ограничения
- Ккал и БЖУ считает только `lib/nutrition.ts`; клиент для превью вызывает те же функции (`.claude/rules/ui.md`).
- Все числа — в `lib/config.ts`: `QUICK.recentLimit = 8`, `QUICK.maxFavorites = 100`, `QUICK.undoMs = 5000`, `QUICK.kcal = { min: 1, max: 5000 }`, `QUICK.repeatNames = 2`, `MEAL_BY_HOUR`.
- Схема — только через `/db-change`: показать SQL владельцу, ждать «ок» до `pnpm db:migrate`.
- Каждый запрос фильтрует по `user_id` сессии; id из браузера — через zod.
- Тексты — из `lib/i18n/ru.ts`; уведомления — только известные ключи (`lib/toast.ts`), текст из URL не выводится.
- 375 px, тап-зоны ≥ 44 px; формы и поиск на экранах, куда возвращаются по ссылке, — `key` из входных данных или `ResetOnHide`.
- Коммиты — Conventional Commits, без строк атрибуции. Новых зависимостей нет.

## На что смотреть при ревью
1. Быстрое добавление продукта, чья последняя порция удалена, — запись по снимку той порции, без ошибки (тест в задаче 4).
2. Две вкладки: «Повторить» во второй, когда приём уже заполнен первой, — ответ «уже заполнено», без дублей (тест в задаче 4).
3. «Отменить» с подменённым `undo` (чужие id, мусор, слишком много id) — удаляются только свои записи, ошибок нет (тесты в задачах 2 и 4).
4. Быстрая запись в недавних, избранном и источнике повтора — недавние и избранное её пропускают, повтор копирует как есть (тесты в задачах 3 и 4).
5. Удалённый продукт в избранном и недавних — не показывается; быстрое добавление по нему — «not_found» (тесты в задачах 3 и 4).
