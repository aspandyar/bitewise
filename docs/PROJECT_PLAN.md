# Project: Bitewise

> Наверх: [[Bitewise]] · связано: [[Projects/Bitewise/features|features]] · [[Projects/Bitewise/architecture|architecture]] · [[Projects/Bitewise/notes|notes]]

## Цель
Быстро и честно записывать, что съел, и видеть, сколько осталось до нормы ккал/БЖУ. Запись одного приёма пищи — не дольше 15 секунд.

Принцип: **числа даёт база продуктов и формула, а не нейросеть.** AI ускоряет ввод (фото, свободный текст), но итог всегда считается как `Σ граммы × ккал_на_100г / 100` и подтверждается пользователем.

---

## Текущий статус
Этапы 0–5 и 6а готовы, 6б готов без сервера: каркас (`ft/karkas`); вход + профиль + норма (`ft/auth-profile`): Auth.js v4 (email + пароль, JWT), открытая регистрация, роли user/manager/admin (админ — `pnpm admin:bootstrap`), онбординг, норма ккал/БЖУ в режимах авто/вручную; база продуктов (`ft/foods`): свои продукты и порции, поиск по 1–2 буквам и с опечатками, сид 222 продуктов (`pnpm seed:build`, `pnpm db:seed`); дневник (`ft/diary`): день на главной, приёмы пищи, записи по граммам или порциям со снимком продукта, правка и удаление, итоги и прогресс к норме, навигация по дням в часовом поясе пользователя; блюда (`ft/recipes`): своё блюдо из продуктов (граммами или порциями), вес готового блюда и число порций → ккал на 100 г и «1 порция», живой пересчёт при правке ингредиентов, в дневник — как обычный продукт; полировка (5 партий, PR #77, #79, #80, #84, #85); скорость ввода (`ft/quick`): избранное (☆ на продукте и блюде), недавние с прошлым количеством — запись в 2 тапа с «Отменить», «Повторить» пустой приём пищи одним тапом, быстрый ввод «просто N ккал», «Сегодня / Вчера», живой итог ккал на экране количества, возврат к записи после «Добавить свой продукт», приём пищи по времени суток из блюда; внешний вид и PWA (`ft/pwa`): тема и акцентный цвет на экране «Оформление», manifest и иконки, service worker со страницей «Нет сети», плашка при обрыве, «Установить на телефон». прод в репозитории (`ft/deploy`, этап 6б): образ (Next standalone + скрипты релиза), `docker-compose.prod.yml` с nginx + TLS и certbot, релиз с бэкапом, миграциями, сидом, админом и откатом, бэкап по cron и ежемесячная проверка восстановления, сборка образа в GHCR по кнопке, полный CSP, семафор на scrypt, runbook `docs/deploy.md`; весь стек проверен на ноутбуке; прод до первого деплоя (`ft/hardening`, #101–#104): своя роль Postgres у приложения, секреты по контейнерам, read-only `app`, образы по digest, вход при перегрузке; повтор действий без дублей (`ft/retry-safe`, #95); полировка 6 (`ft/polish-6`): логи без SQL-параметров, повтор под другим входом, регистрации и «Повторить», формы и экраны, оформление, PWA (#76, #81–#83, #86–#93, #96–#99, #107). Следующий шаг — первый `/deploy`, когда будут сервер и домен (#8); затем v0.2.

## Этапы (порядок веток = порядок сборки)

### MVP — «дневник, которым можно пользоваться каждый день»
| # | Ветка | Что сделать | Готово, когда |
| --- | --- | --- | --- |
| 0 | `ft/karkas` | Next.js + TS strict + Tailwind v4 + Vitest + ESLint; Drizzle + Postgres в `docker compose`; `lib/config.ts`; CI (lint + test) | `docker compose up -d db && pnpm db:migrate && pnpm dev` поднимает пустую главную; `pnpm lint` и `pnpm test` зелёные |
| 1 | `ft/auth-profile` | регистрация/вход; профиль (пол, дата рождения, рост, вес, активность, цель); расчёт нормы | после онбординга видна норма ккал/БЖУ, её можно переопределить вручную |
| 2 | `ft/foods` | таблица продуктов (на 100 г), CRUD своих продуктов, порции («1 шт = 60 г»), поиск (`pg_trgm`), сид базовых продуктов | нашёл «гречка» за 1–2 буквы, добавил свой продукт |
| 3 | `ft/diary` | день → приёмы пищи (завтрак/обед/ужин/перекус) → записи «продукт × граммы»; итоги и прогресс-бары | добавил/изменил/удалил запись, итоги пересчитались |
| 4 | `ft/recipes` | свои блюда из ингредиентов; вес готового блюда → ккал на 100 г и на порцию | «борщ» из 8 ингредиентов добавляется в дневник как один продукт |
| 5 | `ft/quick` | избранное, недавние, «повторить вчерашний завтрак», быстрый ввод «просто N ккал» | типичный завтрак записывается в 2 тапа |
| 6а | `ft/pwa` | manifest + service worker (страница «Нет сети»), иконки, плашка `useOffline`, строка «Установить на телефон»; тема «Системная / Светлая / Тёмная» и акцентный цвет (cookie + скрипт в `<head>` — без мигания, `theme-color` под тему), экран «Оформление» | тема и акцентный цвет переключаются вручную и запоминаются; prod-сборка ставится как приложение, без сети — своя страница |
| 6б | `ft/deploy` | Dockerfile, nginx + TLS на VPS, бэкап `pg_dump` по cron; #17–#26 (bootstrap и сид при деплое, заголовки nginx и CSP, `NEXTAUTH_*` при сборке, семафор scrypt, локаль БД) | приложение стоит на телефоне и живёт на своём домене |

## Правила работы
- Одна ветка = один этап, мерж в `master` после зелёного CI.
- После каждого этапа обновить «Текущий статус» и записать решения в [[Projects/Bitewise/notes|notes]].
- Не начинать v0.3, пока MVP не прожил на телефоне хотя бы неделю — AI должен ускорять работающий дневник, а не заменять его.
