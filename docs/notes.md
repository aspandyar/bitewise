| 2026-10-10 | Углеводы хранятся без клетчатки, клетчатка — отдельно (`fiber_100`); при импорте USDA `carbs = by difference − fiber` | так считают российские этикетки и таблицы; у гречки разница ~10 г на 100 г |

| 2026-10-10 | `foods` + `food_portions`: `owner_id` null — общий продукт из сида, CHECK связывает `source`, `owner_id`, `seed_key`; `search_name` — generated column `replace(lower(name), 'ё', 'е')` с GIN `gin_trgm_ops` | «свекла» находит «Свёклу», регистр не важен; база сама не даст смешать свои продукты и сид |
| 2026-10-10 | `pg_trgm` — отдельной custom-миграцией (`drizzle-kit generate --custom`), строку вписал пользователь | правка `db/migrations/**` запрещена настройками; расширение доедет до прода миграцией |
| 2026-10-10 | Поиск: до 3 символов — начало любого слова (`LIKE`, экранирование `%`/`_`/`\`), с 3 — ещё `word_similarity` (`<%`); порог 0.4 в config; свои продукты выше общих | триграммы на 1–2 буквах бесполезны; 0.4 пропускает «грчка» (0.44) и отсекает «молоко» на «гречко» (0.14) |
| 2026-10-10 | Поиск с клиента — `GET /api/foods/search` (сессия → лимит 120/мин на пользователя → zod `foodQuerySchema`), логика в чистом `handleFoodSearch`; клиент — debounce 250 мс + `AbortController` | выбор пользователя; эндпоинт пригодится выбору продукта в дневнике |
| 2026-10-10 | Сид: `pnpm seed:build <каталог CSV SR Legacy>` собирает `db/seed/foods.json` из `sources/usda.json` (209) и `sources/label.json` (13); `pnpm db:seed` — upsert по `seed_key`, исчезнувшие ключи получают `deleted_at`; архив USDA — в `.cache/` вне git | числа только из данных; повторный запуск безопасен при каждом деплое |

## ❓ Открытые вопросы
- [x] Авторизация: Auth.js v4, Credentials + JWT (этап 1).
- [x] Мультипользовательская модель, регистрация открыта всем; роли `user` / `manager` / `admin` (этап 1).
- [x] Сид-набор продуктов: USDA + перевод + дополнения по ГОСТ/упаковкам, одна база с меткой `source` (этап 2).
- [ ] Домен и проверка, что имя Bitewise свободно (домен, App Store/Google Play на будущее).
- [ ] Какая модель для фото: сравнить точность/цену на 20 своих тестовых фото.
- [ ] Хранить ли фото еды (приватность, место) — по умолчанию нет.
- [ ] Нужен ли офлайн-ввод с синхронизацией позже или достаточно онлайна.
- [ ] `import "server-only"` для `db/client.ts` / `lib/env.ts`: ломает запуск через tsx (сид, drizzle-kit) — решить на этапе 1, когда появятся клиентские компоненты.
- [x] Захват email из allowlist — снят: allowlist убран, регистрация не даёт прав; админ создаётся только `pnpm admin:bootstrap`, который падает, если email уже занят обычным аккаунтом.
- [ ] Боты и перебор email при открытой регистрации (ответ «не удалось» выдаёт, что адрес занят): капча или подтверждение почты («проверьте ящик» в обоих случаях).
- [ ] Будущий сброс пароля по почте: для роли `admin` запрещён, ответ как для несуществующего email. Проверять по роли, не по адресу.
- [ ] Пароль админа хранится в `.env` постоянно (вариант Б): `.env` с правами 600, не в образе и не в git, бэкапы `.env` — отдельно и закрыто.
- [ ] Роль и пароль в JWT — снимок на момент входа: смена роли или пароля применяется при следующем входе. Привилегированные действия читают роль из БД (`changeUserRole` так и делает).
- [ ] Блокировка чужого аккаунта 10 неверными паролями за 15 мин (лимит по аккаунту). Смягчение: не считать попытки с IP, с которых уже был успешный вход.
- [ ] Этап 6: `pnpm admin:bootstrap` при каждом деплое до старта приложения; nginx дописывает `X-Forwarded-For` (`proxy_add_x_forwarded_for`), порт приложения наружу не публикуется (обязательно: без IP регистрация не ограничена), `limit_req` на вход и регистрацию, HSTS и полный CSP, `NEXTAUTH_*` нужны уже при сборке образа, семафор на scrypt.
- [ ] Отзыв JWT-сессий (`tokenVersion`), когда появится смена пароля.
- [ ] UX нормы: ручные ккал не согласуются с БЖУ; нет подсказки, что ручная норма не пересчитывается от профиля.
- [ ] Нужен ли dev-сервис `app` в compose или хватит `pnpm dev` (prod-образ — этап 6).
- [ ] Свой продукт: проверять ли согласованность ккал с `4Б + 9Ж + 4У` (сейчас — только сумма граммов ≤ 100).
- [ ] Лимит 20 своих порций на продукт может стать 21 при двух одновременных отправках — UX-лимит, не защита.
- [ ] Этап 6: `pnpm db:seed` при каждом деплое (после миграций); проверить `CREATE EXTENSION pg_trgm` от владельца БД на проде.
- [ ] Подпись источника для продуктов из ВкусВилла: сейчас «упаковка» / «Сайт производителя» — точнее «Этикетка (ВкусВилл)».
- [ ] Атрибуция USDA FoodData Central в интерфейсе (public domain, не обязательна, но вежлива).
- [ ] `notFound()` внутри `<Suspense>` рендерит русскую 404, но HTTP-статус может остаться 200 (стриминг) — проверить на этапе 6.
- [ ] Этап 6: проверить `datctype` прод-БД — `lower()` в `search_name` понижает кириллицу только в UTF-8-локали (локально `en_US.utf8`).
- [ ] Ревью этапа 2, отложено (мелкое): `deleteOwnPortion` не сверяет `foodId` и видимость продукта; лог ошибки поиска содержит SQL-параметры (запрос и userId); `source_url` без CHECK в БД и без проверки протокола при выводе; `isOwn` верен только вместе с `visibleTo`; копия может получить больше 20 своих порций; `Math.round(value * 100)` в `lib/foods/schema.ts` — взять масштаб из `NUTRIENT_STORAGE_DECIMALS`; символы `·`, `—`, `:` прямо в JSX.
- [ ] UX поиска и форм (ui-checker, этап 2): «Греческий йогурт» выше «Гречки» по «греч» (короче — выше?); нечёткие совпадения на коротких запросах; `autoFocus` поиска; Enter открывает первый результат; своя кнопка очистки 44 px вместо встроенного «×»; «Добавить свой» с предзаполненным названием; после удаления на `/foods` может остаться старая выдача (состояние сохраняет `cacheComponents`); «Обязательное поле» для пустых; сброс ошибки при правке поля; числа с запятой в выводе; тосты «Сохранено/Удалено/Копия создана»; источник копии («Копия: USDA»); фокус после добавления порции; ккал на порцию; «Повторить» при ошибке поиска; одинаковая подпись «Углеводы без клетчатки».
