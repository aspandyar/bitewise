## ✅ Принятые решения
| Дата | Решение | Почему |
| --- | --- | --- |
| 2026-10-08 | Название — **Bitewise** | на английском, коротко, «с умом про каждый кусок» |
| 2026-10-08 | Стек: Next.js + TypeScript + Postgres | один язык для фронта и бэка, Docker на своём VPS |
| 2026-10-08 | Бэкенд нужен | ключи AI нельзя держать в браузере + синхронизация между устройствами |
| 2026-10-08 | PWA вместо нативного приложения | камера и установка на телефон работают и так |
| 2026-10-08 | Калории считает математика по базе, AI только распознаёт «что и сколько» | точно, проверяемо, бесплатно; AI ошибается в числах |
| 2026-10-08 | AI через абстракцию провайдера (OpenAI / Anthropic) | сменить модель правкой конфига |
| 2026-10-08 | Фото → карточка подтверждения, мини-чат — опционально позже | подтверждение быстрее и надёжнее чата |
| 2026-10-08 | Приложение общее, без привязки к Obsidian-данным (рецепты, нормы, лог) | отдельный продукт со своей логикой |
| 2026-10-09 | Комментарии в коде — на английском, документация в `docs/` — по-русски | код читается без перевода, заметки остаются на родном языке |
| 2026-10-09 | Основная ветка — только `master`, `main` не используется | так решено для репозитория; ревью — `git diff master...HEAD` |

| 2026-10-09 | Шрифт — системный стек, без `next/font` | кириллица везде, без скачивания шрифтов при сборке |
| 2026-10-09 | TS: `strict` + `noUncheckedIndexedAccess`; `pnpm lint` = `eslint . && next typegen && tsc --noEmit` | типы роутов (`LayoutProps`) генерирует Next, без typegen `tsc` падает |
| 2026-10-09 | Prettier + `eslint-config-prettier`; `docs/`, `.claude/`, `CLAUDE.md` исключены из Prettier | один стиль кода без споров с ESLint; Obsidian-заметки форматируются вручную |
| 2026-10-09 | Драйвер БД — `postgres` (postgres.js), не `pg` | без нативных модулей, нативно поддержан Drizzle, проще в Docker |
| 2026-10-09 | `tsx` для `db:seed` | запуск TS-скрипта без отдельной сборки; `.env` — через `node --env-file-if-exists` |
| 2026-10-09 | `pnpm-workspace.yaml`: `esbuild: true`, `sharp: false`, `unrs-resolver: false` | esbuild нужен drizzle-kit/tsx; `sharp` пересмотреть на этапе 6 (`next/image` в standalone) |
| 2026-10-09 | Dev-Postgres на `127.0.0.1:5433`, а не 5432 | 5432 занят другим локальным проектом; в prod-compose (этап 6) порт не публикуется вовсе |
| 2026-10-09 | Тестовая база `bitewise_test` создаётся init-скриптом в том же контейнере | один контейнер; скрипт срабатывает только на пустом volume — после смены нужен пересоздаваемый volume |
| 2026-10-09 | `calcBmrKcal` бросает `RangeError` на вес/рост ≤ 0, возраст < 0, NaN | реалистичные диапазоны проверяет zod в формах (этап 1), функция лишь не даёт «правдоподобного» числа из мусора |
| 2026-10-09 | Нормы БЖУ (г/кг белка, доля жиров) не заведены в `config.ts` | решаются на этапе 1 вместе с функцией и тестами |
| 2026-10-10 | Сид продуктов — подмножество USDA FoodData Central (SR Legacy / Foundation, public domain) с переводом названий; продукты, которых нет в USDA (ряженка, творог 5/9 %, сметана 20 %), — по ГОСТ/упаковкам с указанием источника | точные данные, чистая лицензия, проверяемо по fdc_id; AI числа не пишет |
| 2026-10-10 | Одна общая база продуктов с полем `source` (метка в поиске), без выбора источника пользователем; не согласен с числами — своя копия продукта | базовые продукты расходятся между источниками на 5–10 %, меньше ошибки взвешивания; выбор источника ломает поиск, рецепты и дневник (`food_id`) |
| 2026-10-10 | Углеводы хранятся без клетчатки, клетчатка — отдельно (`fiber_100`); при импорте USDA `carbs = by difference − fiber` | так считают российские этикетки и таблицы; у гречки разница ~10 г на 100 г |
| 2026-10-10 | Продукты — в Postgres; `db/seed/foods.json` — только исходник сида в репо, `pnpm db:seed` делает upsert; Open Food Facts целиком не импортируем, кэшируем по штрихкоду (этап 7) | поиск `pg_trgm`, свои продукты и связи работают только в БД; объём для Postgres несущественный |
| 2026-10-10 | `foods` + `food_portions`: `owner_id` null — общий продукт из сида, CHECK связывает `source`, `owner_id`, `seed_key`; `search_name` — generated column `replace(lower(name), 'ё', 'е')` с GIN `gin_trgm_ops` | «свекла» находит «Свёклу», регистр не важен; база сама не даст смешать свои продукты и сид |
| 2026-10-10 | `pg_trgm` — отдельной custom-миграцией (`drizzle-kit generate --custom`), строку вписал пользователь | правка `db/migrations/**` запрещена настройками; расширение доедет до прода миграцией |
| 2026-10-10 | Поиск: до 3 символов — начало любого слова (`LIKE`, экранирование `%`/`_`/`\`), с 3 — ещё `word_similarity` (`<%`); порог 0.4 в config; свои продукты выше общих | триграммы на 1–2 буквах бесполезны; 0.4 пропускает «грчка» (0.44) и отсекает «молоко» на «гречко» (0.14) |
| 2026-10-10 | Поиск с клиента — `GET /api/foods/search` (сессия → лимит 120/мин на пользователя → zod `foodQuerySchema`), логика в чистом `handleFoodSearch`; клиент — debounce 250 мс + `AbortController` | выбор пользователя; эндпоинт пригодится выбору продукта в дневнике |
| 2026-10-10 | Сид: `pnpm seed:build <каталог CSV SR Legacy>` собирает `db/seed/foods.json` из `sources/usda.json` (209) и `sources/label.json` (13); `pnpm db:seed` — upsert по `seed_key`, исчезнувшие ключи получают `deleted_at`; архив USDA — в `.cache/` вне git | числа только из данных; повторный запуск безопасен при каждом деплое |
| 2026-10-10 | Продукты «с этикетки» — со страниц собственной марки ВкусВилла (данные этикетки поставщика на 100 г; при нескольких поставщиках — первый) | сайт Простоквашино недоступен, поиск давал только пользовательские записи health-diet.ru |
| 2026-10-10 | Скрипты (`db/seed/index.ts`, `scripts/*`) — `main()` без top-level await, пути от корня репо | `tsx` собирает их в CommonJS (в `package.json` нет `"type": "module"`) |
| 2026-10-11 | «Сегодня» — по часовому поясу браузера (cookie `tz`, ставит `TimeZoneCookie`), без cookie — `Asia/Almaty` | в UTC ночной перекус в Алматы уходит во «вчера»; без миграции, поездки подхватываются сами |
| 2026-10-11 | Запись дневника хранит снимок продукта на 100 г, название и граммы; итоги считает `lib/nutrition.ts` | правка граммов пересчитывается точно, без накопления округлений; правка и переименование продукта историю не меняют |
| 2026-10-11 | Запись помнит снимок порции (название, граммы) и количество; количество дробное 0,25–50, хранится до сотых | в дневнике «2 × 1 шт (120 г)»; удаление порции не трогает прошлые записи |
| 2026-10-11 | Добавление — отдельными экранами: `/diary/add` (поиск) → `/diary/add/[foodId]` (количество) → день | «назад» работает естественно, серверные компоненты + один клиентский поиск |
| 2026-10-11 | Удаление записи — настоящее, правка — только количество и приём; другая порция = удалить и добавить | на запись никто не ссылается; снимок остаётся честным |
| 2026-10-11 | Лимиты дневника: 100 записей в день и 100 000 на аккаунт, добавление под `pg_advisory_xact_lock` пользователя | security-ревью: перебор дат скриптом давал ~1 млн строк; лимит должен держаться и при параллельных запросах |
| 2026-10-11 | Формы и поиск дневника перемонтируются по `key` | `cacheComponents` хранит скрытые экраны с состоянием: без ключа форма подставляла прошлый приём пищи и откатывала граммы |
| 2026-10-12 | Блюдо — строка `foods` (`source = 'user'`, владелец) + `recipes` (вес готового, порции) + `recipe_items`; признак «блюдо» — наличие строки `recipes` (EXISTS), а не новое значение enum | поиск, порции, дневник, будущие избранное и AI-сопоставление видят один `food_id`; drizzle применяет миграции одной транзакцией, а новое значение enum нельзя использовать в той же транзакции |
| 2026-10-12 | Цифры блюда живые: `calcRecipe` → строка `foods` при каждом изменении блюда, правке своего продукта-ингредиента и сиде; дневник хранит снимок | ингредиенты уточняются — блюдо точнее; история не меняется |
| 2026-10-12 | Нет веса готового блюда — делим на сырой вес; вес не меньше max(Б+Ж+У, ккал × 100 / 900), форма не даёт сохранить меньше | салат без взвешивания считается честно; опечатка «10 г» не даёт 4000 ккал на 100 г и не переполняет `numeric(8,2)` |
| 2026-10-12 | Порция блюда «1 порция» = вес / порций — единственная `food_portion` строки-блюда, только в пределах 0,1–5000 г | экран количества дневника показывает её без изменений; 20 кг × 50 переполнили бы столбец |
| 2026-10-12 | Ингредиент — граммами или порциями (снимок, как в дневнике); блюдо в блюде нельзя; удалённый продукт остаётся в составе | «2 шт (120 г)» без взвешивания; без циклов пересчёта |
| 2026-10-12 | Запись в блюдо — под `SELECT … FOR UPDATE` строки блюда владельца; пересчёт из правки продукта и сида — та же блокировка по порядку id; удаление блюда удаляет состав | security-ревью: advisory-ключ можно было занять чужим id, пересчёт гонялся с правкой и копил удалённые блюда |
| 2026-10-12 | `ResetOnHide` и сброс подтверждения удаления в эффекте-очистке | `cacheComponents` прячет экран со состоянием: возвращались несохранённые значения и взведённое «Точно удалить» |
| 2026-10-13 | Живой итог ккал на экране количества: клиент вызывает ту же чистую функцию из `lib/nutrition.ts`, сервер пересчитывает при сохранении | цифра видна до «Добавить»; формула одна, расхождений нет (правило `ui.md` обновлено) |
| 2026-10-13 | Еда после полуночи — кнопка «записать во вчера», граница дня остаётся 00:00 | день не «плывёт» в отчётах; редкий случай закрывается одним тапом |
| 2026-10-13 | Ручная норма — подсказки, а не автоматика: «по БЖУ выходит N ккал» и «ручная норма не меняется от профиля» | пользователь сам решает, что править; несогласованность видна |
| 2026-10-13 | Свой продукт: если ккал расходятся с 4·Б + 9·Ж + 4·У, — предупреждение, сохранить можно; порог — в `lib/config.ts` | ловит опечатки; формула врёт для алкоголя, полиолов и неточных этикеток |
| 2026-10-13 | Атрибуция USDA FoodData Central — строкой в интерфейсе | данные public domain, указать источник вежливо |
| 2026-10-13 | Акцентный цвет на выбор — в этапе 6 вместе с темой, хранится в cookie рядом с темой | одна настройка внешнего вида, сервер рисует без мигания, без миграции |
| 2026-10-14 | Лимиты на пользователя (записи дневника, свои продукты, свои порции) держит один advisory-замок на пользователя — `db/locks.ts` | параллельные отправки не проходят проверку счётчика вместе; один ключ — нельзя разъехаться |
| 2026-10-14 | В лог ошибок БД — только класс и SQLSTATE-код (`lib/log.ts`), без SQL, параметров и текста Postgres | текст поиска, id, email и хеш пароля не попадают к тем, кто читает логи |
| 2026-10-14 | Порция × количество обязаны укладываться в диапазон граммов записи (0,1–5000 г) — в дневнике и в блюдах | иначе запись нельзя было бы потом сохранить «граммами» |
| 2026-10-14 | Cookie `tz` принимает только имена IANA; смещения (`+23:59`) — пояс по умолчанию | `Intl` принимает смещения до ±23:59, «сегодня» уезжало почти на двое суток |
| 2026-10-14 | Пустое обязательное поле — «Введите …», а не диапазон; числа в сообщениях — с запятой и группами тысяч от пяти цифр (`lib/i18n/number.ts`) | «От 0.1 до 5000» на пустом поле не говорит, что делать |
| 2026-10-14 | Запись порции — «1,5 × 1 шт (крупное) · 75 г»: «×» остаётся | без «1 » получилось бы «2 порция», «2 стакан» |
| 2026-10-14 | «Углеводы без клетчатки» — у значений продукта и блюда; в итогах дня и норме — «Углеводы» | там узкие колонки и сумма за день |
| 2026-10-14 | Запись или ингредиент, сохранённые граммами, при правке можно перевести на порцию своего продукта (уточняет решение 2026-10-11: у записи с порцией по-прежнему меняется только количество) | взвесил, потом понял, что удобнее «2 шт»; удалять и добавлять заново — лишние тапы |
| 2026-10-14 | Степпер количества шагает на целую порцию (`DIARY_LIMITS.portionCount.step = 1`), дроби вводятся | «3 шт» — два тапа, а не четыре |
| 2026-10-14 | У продукта без порций поле граммов открывается со 100 г, выделенными (`DIARY_LIMITS.grams.default`) | один тап добавляет 100 г, ввод заменяет число |
| 2026-10-14 | Формы: после неудачной отправки фокус на первом поле с ошибкой; ошибка поля скрывается, как только его правят (`usePreservingFormAction`) | сразу видно, что исправить, и исправленное не горит красным |
| 2026-10-14 | Нечёткий поиск требует ещё и `strict_word_similarity` ≥ 0,28 (`<<%`), им же разбиваются равные совпадения по началу | опечатки («малоко», «грчка») находятся, а «борщ» → «Перец», «рис» → «Рикотта» — нет; «греч» → сначала «Гречка» |
| 2026-10-14 | «Добавить свой» из пустого поиска открывает форму с запросом в названии (`?name=`, с заглавной) | не набирать название второй раз |
