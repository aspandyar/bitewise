## ❓ Открытые вопросы
- [x] Авторизация: Auth.js v4, Credentials + JWT (этап 1).
- [x] Мультипользовательская модель, регистрация только по `SIGNUP_ALLOWLIST` (этап 1).
- [ ] Откуда брать сид-набор базовых продуктов на русском (собрать вручную / перевести часть USDA)?
- [ ] Домен и проверка, что имя Bitewise свободно (домен, App Store/Google Play на будущее).
- [ ] Какая модель для фото: сравнить точность/цену на 20 своих тестовых фото.
- [ ] Хранить ли фото еды (приватность, место) — по умолчанию нет.
- [ ] Нужен ли офлайн-ввод с синхронизацией позже или достаточно онлайна.
- [ ] `import "server-only"` для `db/client.ts` / `lib/env.ts`: ломает запуск через tsx (сид, drizzle-kit) — решить на этапе 1, когда появятся клиентские компоненты.
- [ ] Захват email из allowlist: первый зарегистрировавшийся получает аккаунт без подтверждения владения адресом. Варианты: инвайт-токен, создание пользователей CLI-скриптом, подтверждение по почте. Пока — регистрироваться сразу после деплоя.
- [ ] Блокировка чужого аккаунта 10 неверными паролями за 15 мин (лимит по аккаунту). Смягчение: не считать попытки с IP, с которых уже был успешный вход.
- [ ] Этап 6: nginx дописывает `X-Forwarded-For` (`proxy_add_x_forwarded_for`), порт приложения наружу не публикуется, `limit_req` на вход и регистрацию, HSTS и полный CSP, `NEXTAUTH_*` нужны уже при сборке образа, семафор на scrypt.
- [ ] Отзыв JWT-сессий (`tokenVersion`), когда появится смена пароля.
- [ ] UX нормы: ручные ккал не согласуются с БЖУ; нет подсказки, что ручная норма не пересчитывается от профиля.
- [ ] Нужен ли dev-сервис `app` в compose или хватит `pnpm dev` (prod-образ — этап 6).
