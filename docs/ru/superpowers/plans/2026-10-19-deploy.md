# Этап 6б — `ft/deploy`: план реализации

> **Для исполнителя:** обязательный навык — superpowers:executing-plans (или superpowers:subagent-driven-development). Шаги — чекбоксы `- [ ]`.

**Цель:** прод в репозитории и проверен на ноутбуке — образ, compose, nginx + TLS, релиз, бэкапы, runbook; плюс код по #20, #23 и проверки #24, #26.

**Архитектура:** один образ (`Dockerfile`, standalone Next + `ops/*.js`, собранные esbuild); `docker-compose.prod.yml` — `db`, `app`, `nginx`, `certbot`; шаги релиза — `docker/scripts/*.sh`; образ собирает GitHub Actions в GHCR. Чистая логика (семафор, проверки БД, health, заголовки) — в `lib/` с тестами; shell и compose проверяются прогоном стека на ноутбуке (podman).

**Стек:** Next.js 16 standalone, Node 24, drizzle-orm migrator, postgres 17-alpine, nginx (официальный образ, шаблоны envsubst), certbot, GitHub Actions + GHCR, esbuild.

**Спека:** `docs/ru/superpowers/specs/2026-10-19-deploy-design.md`

## Глобальные ограничения
- Значения — в `lib/config.ts`: `PASSWORD_HASH.maxConcurrent = 2`, `PASSWORD_HASH.maxQueued = 20`, `SECURITY_HEADERS` (CSP, Permissions-Policy), `HEALTH.timeoutMs`. Значения инфраструктуры (порты, сроки, пути) — переменные в compose/скриптах с дефолтами, перечисленные в `.env.example`.
- `.env` и `.env.*` не трогать (кроме `.env.example`). Для локального прогона прод-стека — gitignored каталог `.local-prod/` с `app.env`.
- Секреты — только в env на сервере; в образе — несекретные заглушки на стадии сборки.
- Правила `.claude/rules/deploy.md`: multi-stage, standalone, не root; порт БД наружу не публикуется; миграции до старта нового контейнера; бэкап по cron + проверка восстановления раз в месяц; деплой только вручную.
- Скрипты — `bash` с `set -euo pipefail`, работают и в Docker, и в podman (`docker compose`).
- Коммиты — Conventional Commits, без строк атрибуции. Новая зависимость — только `esbuild` (dev).

## На что смотреть при ревью
1. nginx стартует, когда контейнер `app` ещё не поднят или упал, и отдаёт 503 с `Retry-After`, а не падает «host not found» (проверка в задаче 7).
2. Клиент присылает свой `X-Forwarded-For: 1.2.3.4` — лимиты приложения считают реальный IP (крайний справа от nginx), а не подставленный (проверка в задаче 7).
3. Миграция падает посреди релиза — `app` остаётся на прошлом теге и продолжает работать (проверка в задаче 7).
4. Повторный релиз того же тега на живой базе — миграции и сид ничего не ломают, админ «up to date» (задача 7).
5. HSTS не прилетает на `localhost` (иначе Chrome навсегда уведёт `http://localhost:3000` dev-сервера на https) (тест в задаче 4, проверка в задаче 7).

```ts
export class BusyError extends Error {
  constructor() {
    super("too many concurrent tasks");
  }
}

// Caps CPU- and memory-heavy work (scrypt takes ~32 MB per hash) so a burst of sign-ins cannot
// starve a small server; past the queue limit callers fail fast instead of piling up.
export function createSemaphore({ maxConcurrent, maxQueued }: { maxConcurrent: number; maxQueued: number }) {
  let active = 0;
  const waiting: (() => void)[] = [];

  function release() {
    const next = waiting.shift();
    if (next) next();
    else active -= 1;
  }

  async function acquire(): Promise<void> {
    if (active < maxConcurrent) {
      active += 1;
      return;
    }
    if (waiting.length >= maxQueued) throw new BusyError();
    // The slot passes straight to the waiter, so `active` stays the same.
    await new Promise<void>((resolve) => waiting.push(resolve));
  }

  return {
    async run<T>(task: () => Promise<T>): Promise<T> {
      await acquire();
      try {
        return await task();
      } finally {
        release();
      }
    },
  };
}
```
