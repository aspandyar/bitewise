# Сканер штрихкодов — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** штрихкод с камеры iPhone (или введённый руками) → свой продукт, общий или из Open Food Facts → экран количества в дневнике или карточка в «Продуктах»; не найдено — форма своего продукта со штрихкодом.

**Architecture:** чистые функции (`lib/foods/barcode.ts` — код, `lib/foods/off.ts` — разбор ответа Open Food Facts) отдельно от ввода-вывода; поиск по коду — `handleBarcodeLookup` по образцу `handleFoodSearch` за route handler `GET /api/foods/barcode`; найденное в Open Food Facts сохраняется общим продуктом `source = 'off'`. Сканер — клиентский слой, библиотека `barcode-detector` (zxing-wasm) грузится динамически, `.wasm` раздаётся со своего сайта.

**Tech Stack:** Next.js 16, Drizzle/Postgres, zod, Vitest; `barcode-detector` (MIT, ponyfill `BarcodeDetector` на zxing-wasm).

**Spec:** `docs/ru/superpowers/specs/2026-10-22-barcode-design.md`

## Global Constraints
- Числа в дневник — только из базы и этикетки; ккал из БЖУ не досчитываются; кДж → ккал делением на 4,184; значения на порцию → на 100 г только при известном весе порции; 100 мл = 100 г.
- Неполные данные (нет ккал или любого из Б/Ж/У, пустое название, цифры вне `FOOD_LIMITS`) = «не найдено» с подсказками.
- Open Food Facts: `GET https://world.openfoodfacts.org/api/v2/product/{code}?fields=…`, свой `User-Agent` (`Bitewise/<версия> (https://github.com/aspandyar/bitewise)`), лимит у них — 15 чтений в минуту на IP: наш общий лимит исходящих — 10 в минуту на процесс.
- Код: только цифры; длины 8, 12, 13, 14; контрольная цифра GS1; хранится как EAN-13 для 12- и 14-значных с лишним нулём (UPC-A `0` + 12 цифр; GTIN-14 с ведущим `0` — без него), иначе как есть.
- Все значения (лимиты, таймаут, User-Agent, пути) — в `lib/config.ts`; тексты — в `lib/i18n/ru.ts`; 375 px, тап-зоны ≥ 44 px, светлая и тёмная тема.
- Схема — только через `/db-change`: SQL показать владельцу и ждать «ок» перед `pnpm db:migrate`.
- Новая зависимость `barcode-detector` — `pnpm add` с подтверждением владельца.
- Документация меняется парой: `docs/ru/` и `docs/en/`.

## Review Focus
1. Камера остаётся включённой после ухода с экрана, сворачивания приложения или скрытия экрана `cacheComponents` — поток должен останавливаться (Task 7, ручная проверка ui-checker + чистая функция остановки).
2. Один код распознан несколько кадров подряд — один запрос и один переход, не три (Task 7, тест `shouldSubmitCode`).
3. Странные цифры из Open Food Facts (строки, отрицательные, ккал 9000, ккал без единиц) — «неполные», а не мусор в базе (Task 3, фикстуры).
4. Один товар как UPC-A и как EAN-13, код с пробелами или вставленный из буфера — одна строка в базе (Task 1).
5. Open Food Facts отвечает 503 / таймаут / исчерпан наш общий лимит — своя база всё равно проверена, ответ «недоступно» (Task 4).
