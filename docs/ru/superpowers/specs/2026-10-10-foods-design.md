# Этап 2 — `ft/foods`: база продуктов, порции, поиск, сид

Дата: 2026-10-10 · Статус: реализовано · Ветка: `ft/foods` (от `master`)

## Цель
Пользователь быстро находит продукт по названию (в том числе с опечаткой) и заводит свои продукты и порции. Это основа дневника этапа 3.

**Готово, когда:** «гречка» находится по 1–2 буквам; свой продукт создаётся и находится поиском; общий продукт копируется к себе; к любому видимому продукту добавляется своя порция. `pnpm lint` и `pnpm test` зелёные, CI зелёный.

## Принятые решения
| Вопрос | Решение | Почему |
| --- | --- | --- |
| Источники | одна общая база с полем `source`; пользователь не выбирает источник; не согласен — копирует продукт к себе | базовые продукты расходятся между источниками на 5–10 %; выбор источника ломает поиск и ссылки `food_id` |
| Общие продукты | только для чтения в приложении; меняются правкой сида и `pnpm db:seed` | редактирование менеджером — вместе с админкой, отдельным этапом |
| Порции | общие (из сида, `user_id = null`) + личные порции пользователя к любому видимому продукту | «моя кружка = 300 г» без копирования продукта и дублей в поиске |
| Углеводы | хранятся без клетчатки; клетчатка — `fiber_100` (может быть null) | так пишут российские этикетки и таблицы |
| Хранение | продукты в Postgres; `db/seed/foods.json` — только исходник сида | поиск `pg_trgm`, свои продукты и связи работают только в БД |
| Данные USDA | CSV-архив SR Legacy (public domain), скачивается один раз в `.cache/usda/` вне git | локально, без API-ключей и лимитов |
| Продукты не из USDA | 10–20 штук с официальных страниц производителей, `source = label`, `source_url` в сиде | проверяемо по ссылке; числа не берутся из памяти модели |
| Поиск с клиента | GET `/api/foods/search?q=` + `fetch` с debounce и `AbortController` | выбор пользователя; обновляется только список, эндпоинт пригодится выбору продукта в дневнике |
| Удаление | только мягкое (`deleted_at`) | на этапе 3 на продукт сошлются записи дневника |

## Вне этапа
- Штрихкод и Open Food Facts (этап 7): `barcode`, `source = off`.
- «Недавние» и «избранное» (этапы 3 и 5).
- Сахар, соль, микроэлементы; бренд отдельным полем.
- Редактирование общих продуктов в интерфейсе (админка).
- Проверка согласованности ккал с БЖУ (`4Б + 9Ж + 4У`) — в открытые вопросы.

## Данные (`db/schema.ts`, через `/db-change`)
Две миграции:
1. **Custom** (`drizzle-kit generate --custom`): `CREATE EXTENSION IF NOT EXISTS pg_trgm;`. Файл создаётся пустым именно для ручного SQL, сгенерированные миграции не правятся. Правка `db/migrations/**` мне запрещена настройками, поэтому эту одну строку вписывает пользователь (или разрешает разовую запись).
2. **Generated**: enum и таблицы ниже.

`food_source` (enum, кортеж `FOOD_SOURCES` в `config.ts`): `user`, `usda`, `label`. Значения `off`, `ai_estimate` добавляются миграциями на своих этапах.

### `foods`
| Поле | Тип | Примечание |
| --- | --- | --- |
| id | uuid pk default random | |
| owner_id | uuid null → users, on delete cascade; индекс | null — общий продукт |
| name | text not null | как показывается |
| search_name | text generated always as `lower(replace(name, 'ё', 'е'))` stored | `lower` в Postgres переводит и `Ё` → `ё`, затем `replace` даёт `е`; GIN-индекс `gin_trgm_ops` |
| kcal_100, protein_100, fat_100, carbs_100 | numeric(8,2) not null | на 100 г; углеводы без клетчатки |
| fiber_100 | numeric(8,2) null | |
| source | food_source not null | |
| seed_key | text null, unique | `usda:<fdcId>` / `label:<slug>` — ключ upsert сида |
| source_url | text null | для `label` |
| deleted_at | timestamptz null | мягкое удаление |
| created_at, updated_at | timestamptz not null default now() | |

CHECK:
- `(source = 'user') = (owner_id IS NOT NULL)`, `(owner_id IS NULL) = (seed_key IS NOT NULL)` — свои продукты не бывают сидом, общие всегда из сида;
- все нутриенты `>= 0`.

### `food_portions`
| Поле | Тип | Примечание |
| --- | --- | --- |
| id | uuid pk default random | |
| food_id | uuid not null → foods, on delete cascade; индекс | |
| user_id | uuid null → users, on delete cascade; индекс | null — общая порция из сида |
| label | text not null | «1 шт», «моя кружка» |
| grams | numeric(8,2) not null, CHECK > 0 | |
| created_at | timestamptz not null default now() | |

### Видимость (каждый запрос репозитория)
- Продукт виден пользователю U: `deleted_at IS NULL AND (owner_id IS NULL OR owner_id = U)`.
- Порция видна U: продукт виден U и `(user_id IS NULL OR user_id = U)`.
- Изменять можно только свой продукт (`owner_id = U`) и только свою порцию (`user_id = U`). Иначе — «не найдено» (404).

**Риски миграции:** новые пустые таблицы, без блокировок. `CREATE EXTENSION pg_trgm` выполняет владелец БД — в образе `postgres` это `bitewise`; на проде проверить на этапе 6.

## Расчёты (`lib/nutrition.ts`, тест первым)
- `calcNetCarbsPer100g(carbsByDifferenceG, fiberG)` = `max(0, carbsByDifference − fiber)`; `fiber = null` → углеводы как есть. RangeError на отрицательные и NaN — как остальные функции модуля.

## Поиск (`lib/foods/search.ts` — чистые функции; `lib/foods/repo.ts` — SQL)
**Нормализация запроса** (`normalizeFoodQuery`): trim, схлопнуть пробелы, нижний регистр, `ё` → `е`. Пустая строка или длиннее `FOOD_SEARCH.maxQueryLength` (50) → 400 (поле ввода ограничено тем же `maxLength`, так что из интерфейса длинный запрос не уходит). `%`, `_`, `\` экранируются для `LIKE`.

**Совпадение** (вместе с видимостью):
- всегда: `search_name LIKE q || '%' OR search_name LIKE '% ' || q || '%'` — начало любого слова;
- если длина ≥ `FOOD_SEARCH.minTrigramLength` (3): ещё `q <% search_name` (word similarity, GIN-индекс); порог `FOOD_SEARCH.wordSimilarityThreshold` (стартовое 0.5, подбирается тестами) через `SET LOCAL pg_trgm.word_similarity_threshold` в транзакции.

**Порядок:** свои → название начинается с q → слово начинается с q → `word_similarity(q, search_name)` по убыванию → `name`. Не больше `FOOD_SEARCH.limit` (20).

**Пустой запрос на экране** (не через API): свои продукты, новые сверху, тот же лимит; если своих нет — подсказка.

## API: `GET /api/foods/search?q=`
1. Сессия первой строкой; нет → 401.
2. Лимит на пользователя: существующий `createRateLimiter`, `RATE_LIMITS.foodSearch` (120 в минуту) → 429.
3. `q` через zod + `normalizeFoodQuery`; пусто или слишком длинно → 400.
4. Ответ `{ items: [{ id, name, kcal100, protein100, fat100, carbs100, source, isOwn }] }`. `owner_id` наружу не уходит; `isOwn` считает сервер. `Cache-Control: no-store`.
5. Ошибка БД → 500 без деталей, `console.error` на сервере.

## Экраны (`app/(app)/foods/`, mobile-first 375 px, тексты из `ru.foods`)
Каждая страница — `<Suspense>` + Content, как на этапе 1; чужое, общее там, где нужно своё, или удалённое → `notFound()`.

| Экран | Содержание |
| --- | --- |
| `/foods` | поле поиска (клиентский компонент: debounce `FOOD_SEARCH.debounceMs` 250 мс, отмена устаревших запросов); список: название, ккал/100 г, Б/Ж/У, метка «моё» / «USDA» / «упаковка»; кнопка «+ Свой продукт»; состояния: загрузка, пусто (ссылка «Добавить свой»), ошибка, 429 «Слишком часто» |
| `/foods/new` | форма: название, ккал, Б, Ж, У, клетчатка (необязательно) на 100 г; запятая как разделитель; после сохранения — карточка |
| `/foods/[id]` | значения на 100 г, источник (для `label` — ссылка); порции: общие + свои (свои удаляются), форма «название + граммы»; своё: «Изменить», «Удалить» (подтверждение → `/foods`); общее: «Скопировать к себе» |
| `/foods/[id]/edit` | та же форма; для общего — 404 |
| Главная | ссылка «Продукты» |

Числа на экранах округляются только при выводе (`formatKcal`, `formatGrams`).

## Серверная логика
- `app/(app)/foods/actions.ts`: `createFoodAction`, `updateFoodAction`, `deleteFoodAction`, `copyFoodAction`, `addPortionAction`, `deletePortionAction`. Каждый: `requireUserId` первой строкой → zod → репозиторий с фильтром по пользователю → `notFound()` при отказе.
- `lib/foods/schema.ts` — zod-схемы продукта и порции, общие для формы и сервера; лимиты `FOOD_LIMITS` / `PORTION_LIMITS` в `config.ts`:
  - название 1–100 символов; ккал 0–900; каждый нутриент 0–100 г; Б + Ж + У + клетчатка ≤ 100 г;
  - порция: название 1–40, граммы 0.1–5000; не больше 20 своих порций на продукт (проверка в репозитории).
- `lib/foods/repo.ts`: `searchFoods`, `listOwnFoods`, `getVisibleFood`, `createFood`, `updateOwnFood`, `softDeleteOwnFood`, `copyFood` (транзакция: продукт + все видимые порции как свои), `listVisiblePortions`, `addPortion`, `deleteOwnPortion`.

## Сид
| Файл | Что |
| --- | --- |
| `db/seed/sources/usda.json` | ~180 записей `{ key, fdcId, name, portions[] }`; названия — по-русски, разговорные («Гречка, крупа сухая», «Гречка варёная») |
| `db/seed/sources/label.json` | 10–20 записей `{ key, name, kcal, protein, fat, carbs, fiber?, sourceUrl, portions[] }` |
| `db/seed/foods.json` | собранный результат, коммитится; его читает `pnpm db:seed` |

**`pnpm seed:build <каталог CSV>`** (`scripts/build-food-seed.ts`; разбор — чистые функции в `lib/foods/usda.ts`):
- из SR Legacy: нутриенты 1008 (ккал), 1003 (белок), 1004 (жиры), 1005 (углеводы by difference), 1079 (клетчатка);
- углеводы — через `calcNetCarbsPer100g`;
- нет `fdcId` или нет любого из ккал/Б/Ж/У → ошибка с ключом продукта, не ноль;
- вывод отсортирован по `key` — стабильный diff.

**`pnpm db:seed`** (`db/seed/index.ts`): zod-проверка `foods.json` → одна транзакция: upsert по `seed_key`, общие порции продукта заменяются, исчезнувшие из файла ключи получают `deleted_at`. Повторный запуск ничего не меняет.

Список названий по категориям (крупы сухие и варёные, мясо и птица, рыба, яйца, молочка, овощи, фрукты и ягоды, орехи, масла, хлеб, бобовые, сладкое, напитки) — на согласование до сборки. Скачивание архива USDA (~7 МБ, fdc.nal.usda.gov) — с отдельного разрешения.

## Тесты
- **unit:**
  - `calcNetCarbsPer100g` — ручные числа и граничные случаи;
  - разбор CSV USDA и сборка сида — на фикстуре из нескольких строк, без сети;
  - `normalizeFoodQuery` и экранирование `LIKE`;
  - zod-схемы продукта и порции: лимиты, запятая, сумма ≤ 100 г.
- **db** (`*.db.test.ts`):
  - видимость: своё / чужое / общее / удалённое;
  - поиск: «г» и «гр» → гречка; «гречко» → гречка; «свекла» → «Свёкла»; свои выше общих; чужих нет;
  - создание, правка, мягкое удаление; отказ на общий и чужой продукт;
  - копирование с порциями; свои порции не видны другим; лимит 20 порций;
  - сид: повторный запуск без изменений; пропавший ключ → `deleted_at`.
- **route handler:** 401 без сессии, 400 на пустой `q`, 429 сверх лимита, в ответе нет `owner_id` (сессия и репозиторий подменяются).
- **В конце:** субагенты reviewer, security-reviewer (новый API), ui-checker (375 px).

## Новые зависимости
Нет. CSV SR Legacy простой (поля в кавычках, без переносов строк внутри) — разбор своей небольшой функцией с тестами; если в реальном файле окажутся сложные случаи — остановлюсь и предложу `csv-parse` с обоснованием.
