# Этап 8 — `ft/body`: вода, вес, статистика

Дата: 2026-10-25 · Статус: в работе · Ветка: `ft/body` (от `master`)

## Зачем
Вторая половина v0.2 «удобство и тело». Дневник отвечает на «сколько я съел сегодня», но не на «как идут дела за неделю» и «куда движется вес». Вода и вес — частые короткие записи, им нужен один-два тапа, а не отдельное приложение.

**Готово, когда:** вода на главной записывается одним тапом; после ввода веса точка и линия среднего появляются на графике, а авто-норма белка пересчитывается; средние ккал и БЖУ и «дни в норме» за неделю на экране «Статистика» сходятся с ручным расчётом; все экраны — на 375 px без горизонтального скролла, в светлой и тёмной теме.

## Цели
- Вода: +250 / +500 мл на главной для открытого дня, «Убрать последнее», прогресс к норме.
- Вес: запись за сегодня (или исправление прошлой), график за 90 дней с линией среднего за 7 дней, история с правкой и удалением.
- Статистика: неделя / месяц — средние ккал и БЖУ в день, «дни в норме», столбики ккал по дням с линией нормы, список прошлых дней со ссылкой в дневник.

## Не цели (в этой ветке → Issues)
- Экспорт CSV.
- Своя норма воды (пока одна для всех из config).
- История норм: «дни в норме» сравниваются с нормой, действующей сейчас.
- Напоминания о воде и взвешивании.
- Графики БЖУ по дням, сравнение периодов.

## Анти-цели
- Ккал, посчитанные в SQL или в компоненте, а не в `lib/nutrition.ts`.
- Библиотека графиков, которая тянет десятки килобайт JS на клиент ради двух простых картинок.
- Средние, которые тянет вниз день, когда приложение просто не открывали.
- Запись воды, для которой нужно больше одного тапа.

## Решения (владелец принял план 2026-10-25)
| Вопрос | Решение |
| --- | --- |
| Вода — одна строка на день или на нажатие | на нажатие (`water_entries`): «Убрать последнее» удаляет последнюю строку дня, повтор запроса не дублирует |
| Норма воды | одна для всех, `WATER.dailyTargetMl = 2000` в config |
| Взвешивания в день | одно: повторный ввод за тот же день заменяет (уникальность `(user_id, date)`) |
| Вес в профиле | самое свежее взвешивание обновляет `profiles.weight_kg` (только эту колонку) и пересчитывает авто-норму (белок — г/кг); ручную норму не трогает. Профиль меняется, только когда сохраняют или удаляют самое свежее взвешивание: правка прошлой недели не отменяет вес, введённый в профиле после. Удалили самое свежее — профиль берёт предыдущее; удалили последнее — вес профиля остаётся. Обратной синхронизации нет |
| «День в норме» | съеденные ккал в пределах ±10 % от нормы (`STATS.inTargetShare`) |
| Какие дни в средних | только дни, где есть хоть одна запись дневника |
| Норма для сравнения | текущая норма по умолчанию (истории норм нет) |
| Период | «Неделя» — 7 дней, «Месяц» — 30 дней, оба заканчиваются сегодня (в поясе пользователя) |
| Графики | SVG на сервере, без зависимостей; геометрия — чистые функции в `lib/chart.ts`, размеры — `CHART` в config. График веса начинается с первого взвешивания, если оно позже начала окна в 90 дней |
| Среднее веса | для каждого дня со взвешиванием — среднее взвешиваний за 7 календарных дней, заканчивающихся этим днём (пропуски не заполняются) |

## Данные
- `water_entries`: `id`, `user_id` → users (cascade), `date`, `ml integer` (CHECK `ml > 0`), `client_request_id`, `created_at`. Индекс `(user_id, date)`, уникальный `(user_id, client_request_id)` где ключ не null.
- `weight_entries`: `id`, `user_id` → users (cascade), `date`, `weight_kg numeric(5,1)` (CHECK `> 0`), `created_at`, `updated_at`. Уникальный `(user_id, date)` — он же индекс и цель upsert; повтор запроса безопасен сам по себе (upsert того же значения).
- Статистика читает строки дневника за период (`date`, снимок на 100 г, `grams`) и считает итоги дня кодом; за месяц это сотни строк.

## Экраны
- **Главная:** блок «Вода» под итогами дня: «750 / 2000 мл», полоска, кнопки «+250», «+500», «Убрать последнее» (только если есть что убирать). В меню внизу — «Вес» и «Статистика».
- **`/body` «Вес»:** форма «Вес сегодня, кг» (подставлено последнее взвешивание за 90 дней, иначе вес профиля); график; история за те же 90 дней (новые сверху) — тап открывает правку `/body/[date]` с удалением. Пусто — подсказка «Запишите первое взвешивание».
- **`/stats` «Статистика»:** переключатель `?period=week|month`; средние ккал/Б/Ж/У в день; «дней в норме: N из M»; столбики ккал по дням (день без записей — пустое место) с линией нормы; список дней с записями (новые сверху) → `/?date=`. Пусто — «За этот период записей нет».

## Безопасность
- Все действия — server actions: `requireActionUser(formData)` для форм, `requireWriteUser()` для «Убрать последнее» и удаления; лимит записи на пользователя (#31).
- Вода: `client_request_id` (#95), лимит `WATER.maxEntriesPerDay` на день; дата — `parseDiaryDate` (не будущее, не раньше `DIARY_LIMITS.minDate`).
- Вода: общий лимит `WATER.maxEntriesTotal` (как у дневника) — скрипт не заполнит все допустимые даты.
- Вес: zod по `PROFILE_LIMITS.weightKg`, дата — `parseDiaryDate`. Удаление — по id: повтор не удалит взвешивание, введённое за тот же день заново, или взвешивание другого аккаунта, вошедшего на том же устройстве (#107). Чужой или несуществующий id ведёт туда же, куда успешное удаление.
- Каждый запрос фильтрует по `user_id`.
