# Bitewise — как ведём работу

> Наверх: [[Bitewise]] · связано: [[Projects/Bitewise/PROJECT_PLAN|PROJECT_PLAN]] · [[Projects/Bitewise/notes|notes]] · [[Projects/Bitewise/development|development]]

Проект строится по этапам из [[Projects/Bitewise/PROJECT_PLAN|плана]]. Код пишет Claude Code, решения и «ок» — за владельцем. Всё, что Claude должен соблюдать, записано в репозитории: `CLAUDE.md`, `.claude/rules/`, `.claude/skills/`, `.claude/agents/`.

## Цикл этапа (`/stage N`)
| Шаг | Что происходит | Кто решает |
| --- | --- | --- |
| 1 | Чтение этапа в плане, `notes.md`, правил для затронутых путей | — |
| 2 | Свежий `master` → ветка `ft/<этап>` | — |
| 3 | Большой этап (новая таблица, экран, внешний API) → brainstorming: вопросы по одному, 2–3 подхода, дизайн по разделам | владелец отвечает на вопросы и выбирает подход |
| 4 | Spec → `docs/ru/superpowers/specs/`, план → `docs/ru/superpowers/plans/` | **«ок» на spec и на план**; выбор исполнения: native или субагенты |
| 5 | Реализация по задачам плана: TDD (тест → красный → код → зелёный), коммит на задачу, журнал в `.superpowers/sdd/<план>/progress.md` | изменения схемы — **«ок» на SQL миграции** |
| 6 | `pnpm lint && pnpm test` до зелёного | — |
| 7 | Ревью субагентами, исправления — тоже через тест | — |
| 8 | «Текущий статус» в плане, решения и открытые вопросы в `notes.md`, обновление spec; изменённые справочные документы — и в `docs/en/` | — |
| 9 | Коммиты (Conventional Commits), итог; push и PR — **только по просьбе** | владелец решает про PR и мерж |

Исполнение плана бывает двух видов:
- **Native** — Claude делает задачи сам, подряд, а в конце идут ревью всей ветки. Так прошли этапы 3 и 4.
- **Subagent-driven** — каждая задача достаётся свежему субагенту, после каждой идёт отдельное ревью. Надёжнее, но дороже.

## Правила (`.claude/rules/`)
Подключаются автоматически по путям файлов, которые трогает правка.

| Файл | Пути | Главное |
| --- | --- | --- |
| `general.md` | всегда | английские комментарии «почему», без магических чисел, zod на любом входе, не выходить за этап |
| `nutrition.md` | `lib/nutrition*`, `lib/config.ts` | чистые функции, единицы в именах, тест с ручными числами, рецепт = сумма / вес готового × 100 |
| `db.md` | `db/**`, `lib/**/repo*.ts` | схема только миграциями, `user_id` + индекс, снимок в дневнике, мягкое удаление, `numeric(8,2)` |
| `ui.md` | `app/**`, `components/**` | 375 px, тап-зоны ≥ 44 px, тексты из `ru.ts`, клиент не считает нутриенты, `key` для форм при `cacheComponents` |
| `api-security.md` | `app/api/**`, `lib/auth/**`, `actions.ts` | сессия первой строкой, чужое → 404, zod, rate limit, без секретов в ответах |
| `testing.md` | тесты | TDD для расчётов, без сети, db-тесты на отдельной базе, тесты не ослаблять |
| `ai.md` | `lib/ai/**`, `app/api/ai/**` | AI возвращает только «что и сколько граммов», числа считает код (этапы 9–12) |
| `deploy.md` | `docker/**`, `Dockerfile`, compose | правила прод-окружения (этап 6) |

## Навыки (`.claude/skills/`)
| Навык | Когда |
| --- | --- |
| `/stage N` | начать этап плана |
| `/db-change` | любое изменение таблиц, колонок, индексов |
| `/food-source` | подключить источник продуктов (Open Food Facts на этапе 7) |
| `/ai-provider` | провайдер AI за интерфейсом `FoodRecognizer` (этапы 9–12) |
| `/deploy` | выкатить `master` на VPS (только вручную, этап 6) |
| `/sync-notes` | перенести статус и решения в Obsidian (только вручную) |

## Субагенты (`.claude/agents/`)
| Агент | Когда | Что делает |
| --- | --- | --- |
| `reviewer` | перед каждым мержем | `git diff master...HEAD` против правил проекта, находки с серьёзностью и сценарием |
| `security-reviewer` | этапы с auth, API, AI; изменения `app/api` и `lib/auth` | IDOR, валидация, лимиты, утечки, злоупотребления |
| `ui-checker` | UI-этапы | сценарии в браузере на 375 px, вёрстка, тексты, скорость ввода |

Агенты код не правят. Их находки разбирает исполнитель:
- **критичные и важные** исправляются с тестом, который сначала падает;
- **мелкие** заводятся GitHub Issue с меткой этапа или `polish`, ссылка — в «Открытые вопросы» `notes.md`.

## Защита от ошибок (`.claude/settings.json`)
- **Без спроса:** `pnpm dev/build/test/lint/db:generate/db:seed`, чтение git, `git add/commit/switch`, `docker compose up/ps/logs`.
- **С подтверждением:** `git push/merge/rebase/reset`, `pnpm add/remove`, `pnpm db:migrate`, `ssh/scp/rsync`.
- **Запрещено:**
  - читать и писать `.env*` (кроме `.env.example`);
  - править `db/migrations/**`;
  - `drizzle-kit push`;
  - `docker compose down -v`, `docker volume rm`;
  - `rm -rf`;
  - force-push.
- **Хук после каждой правки:** Prettier + `eslint --fix` для ts/tsx, Prettier для css/json/md.

## Ветки, коммиты, PR
- **Ветки.** Основная — только `master`. Один этап — одна ветка `ft/<этап>`; служебная работа — `ft/docs` и т. п.
- **Коммиты** по-английски, Conventional Commits (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`). Обычно один коммит на задачу плана плюс коммиты с исправлениями по ревью. Без `Co-Authored-By:` и других строк атрибуции — ни в коммитах, ни в описаниях PR.
- **PR** готов к ревью, в описании — что сделано, зачем, на что смотреть ревьюеру, тест-план. Мерж — после зелёного CI.

## Сессии (чаты) с Claude
Длинная сессия сжимает контекст, а свежая начинает с нуля. Поэтому работа делится так:

| Чат | Что в нём | Почему отдельно |
| --- | --- | --- |
| Один этап — один чат (`/stage N`) | от вопросов до PR | весь контекст этапа в одном месте, журнал в `.superpowers/sdd/` переживает сжатие |
| Полировка | issues с меткой `polish`, когда их накопится на ветку | не раздувает этап |
| Документация и обзоры | README, docs, отчёты | читает много, кода почти не меняет |
| Исследования | выбор модели для фото, Open Food Facts, домен | ответ — рекомендация, код не остаётся |
| Деплой | этап 6, затем `/deploy` | доступ к VPS и опасные команды — отдельно и осознанно |

Перед новым чатом стоит закрыть или запушить предыдущую ветку. Состояние между чатами хранят файлы:
- `PROJECT_PLAN.md` — «Текущий статус»;
- `notes.md` — решения и оглавление открытых вопросов (сами задачи — в GitHub Issues);
- spec и план этапа;
- журнал `progress.md` (вне git);
- память Claude: например, «ветка только `master`», «`.env.example` веду я».

## Документация на двух языках
- `docs/ru/` — основная, по-русски; `docs/en/` — английская, те же имена файлов. В начале каждого файла — ссылка на пару.
- Пары есть у справочных документов: `PROJECT_PLAN`, `features`, `architecture`, `api`, `development`, `deploy`, `workflow`. Меняется один — в том же коммите меняется и второй.
- Только по-русски: `notes.md` (журнал решений) и спеки и планы этапов в `docs/ru/superpowers/`.
- `README.md` — для посетителя GitHub, по-английски; `README.ru.md` — русская версия. Скриншоты — `docs/images/`.

## Obsidian
`docs/ru/*.md` — это заметки волта: frontmatter `type/status/review/tags`, строка «Наверх» и wiki-ссылки. Поэтому Prettier их не форматирует. `/sync-notes` переносит статус в волт вручную, путь к волту лежит в `CLAUDE.local.md`.
