# Bitewise

PWA для учёта еды и калорий: дневник приёмов пищи, своя база продуктов и блюд,
нормы ккал/БЖУ. Позже — сканер штрихкодов и AI-ввод (текст, фото).
План и статус: docs/PROJECT_PLAN.md · фичи: docs/features.md · архитектура: docs/architecture.md
Решения: docs/notes.md

## Стек
Next.js (App Router), React, TypeScript (strict), Tailwind v4, Postgres, Drizzle ORM,
zod, Vitest. Деплой — Docker Compose на своём VPS за nginx. Пакетный менеджер — pnpm.

## Главные правила
- Калории и БЖУ считает ТОЛЬКО код в `lib/nutrition.ts` (чистые функции, покрыты тестами).
  AI никогда не пишет числа в дневник — он возвращает [{ name, grams, confidence }],
  дальше сопоставление с базой и расчёт кодом.
- Все константы и настройки — в `lib/config.ts`. Магических чисел в коде нет.
- Продукты хранятся на 100 г. В записи дневника — снимок ккал/БЖУ на момент добавления.
- Секреты и ключи AI — только в env на сервере. Никогда в клиентском коде.
- AI-провайдер за интерфейсом `lib/ai/provider.ts`; выбор через `AI_PROVIDER` / `AI_MODEL`.
- Подробные правила по областям — в `.claude/rules/`. Процессы — skills (`/stage N`, `/db-change`).

## Соглашения
- Комментарии в коде — только на английском; объясняют «почему», а не «что».
- Идентификаторы, имена файлов, сообщения логов — на английском.
- Документация в `docs/` — по-русски. Тексты интерфейса — через словарь `lib/i18n/ru.ts`.
- Коммиты и PR — по-английски, Conventional Commits (`feat:`, `fix:`, `chore:`, `test:`).
- Без строк соавторства и атрибуции: никаких `Co-Authored-By:` в коммитах и «Generated with …» в описаниях PR.
- Одна ветка = один этап плана (`ft/<этап>`), мерж в `master` после зелёных lint + test.
- Основная ветка — только `master`. Ветку `main` не создавать и не упоминать.
- Схема БД меняется только через миграции drizzle-kit.
- Мобильная вёрстка в первую очередь (ширина 375 px).

## Команды
- `docker compose up -d db` — поднять Postgres
- `pnpm dev` — dev-сервер · `pnpm build` — сборка
- `pnpm test` — Vitest · `pnpm lint` — ESLint + `tsc --noEmit`
- `pnpm db:generate` / `pnpm db:migrate` — миграции · `pnpm db:seed` — сид продуктов

## Как работаем
- Перед кодом — план и моё «ок». Не расширяй задачу за пределы этапа.
- Если не уверен в API библиотеки — смотри актуальную документацию через Context7, не по памяти.
- Ошибся и я поправил — предложи строку в нужный файл `.claude/rules/`, чтобы не повторилось.
